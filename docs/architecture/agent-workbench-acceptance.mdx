## 2026-10-20 调优失败排查

workflow `7` 的任务 `bb256056-f5ea-4cb9-9c88-a7aa673d0349` 于本地时间 17:13:59 以 `Workbench model budget exceeded` 失败。当时网关写死 40 次请求 / 150,000 累计 token，失败记录没有保存用量，不能追溯确切累计数。Codex 两次给 `validate_candidate` 传入 `summary` 被拒；重复发送完整代码和包含重复事件的上下文增加了消耗。

同次基线的 `node_visited` 使用中文节点名，而旧评测器只比较 ID。以原候选和记录事件离线重算，原来的 `0/5` 应为 `2/5`；另外三条仍存在实际行为或文本断言失败，没有修改历史记录或放宽测试集。

修复后节点断言接受 ID 或唯一精确名称；校验工具兼容可选描述；调优证据从 31,391 缩减到 6,472 字符，原始记录保留。预算改为服务器配置，并记录 `model.usage`；超限返回包含真实计数的不可重试错误。仅本地 8016 配置提高到 600,000 token，仍为 40 次请求 / 900 秒。

用户已保存 Variables，因此直接重试旧候选正确触发草稿指纹冲突。排查时以当前草稿建立不可变基线快照 `3e593802-87dd-44a7-b2dd-6d018c6b9d70`，完整保留已保存变量和图；使用原测试集 `d5435a5e-5436-4456-b23c-28892f2fd261` 重试。快照由 DB 客户端生成，明确记录 `origin=draft_snapshot`，没有伪称调用生成模型。

重跑任务 `e0a4d4e4-29bb-4838-be5e-98f30ed96897` 已完成。真实 Codex 共 7 次请求、94,147 累计 token；基线复测 `2/5`，新候选 `47f0e411-141e-4b23-b01d-f3e4f453d48d` 复测 `4/5`，原已通过用例没有回退，运行错误为 0。剩余失败为拒绝沟通场景未出现 `contains("不考虑")` 要求的字面文本；实际已进入礼貌结束节点。固定测试集没有修改。

候选保留全部已填写变量，原草稿没有变更，未应用或发布。候选也改动了问题咨询提示，现有 5 条用例未覆盖知识问答能力，不能把 `4/5` 解读为全部业务质量合格。浏览器截图保存在本地 `run/workbench/tuning-retry-verified.png`，结果摘要在 `tuning-retry-result.json`。
